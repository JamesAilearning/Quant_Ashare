# 688766 停复牌历史缺口：限定隔离操作说明

本说明对应唯一获准策略 `suspend-688766-20251127-20251209`。它允许在严格
核验后继续为其他证券生成候选，**不表示数据完整、历史绩效已验证或生产已验收**。
本文不提供可直接切换生产的整条命令；路径、版本和发布时机须另行核准。

请求必须覆盖整个事件及原有声明范围，仍执行完整响应、父子切片和旧业务键检查。

以下仅列参数接口，不是生产执行命令。四个入口的参数均为
`--suspension-quarantine suspend-688766-20251127-20251209`，默认不选择：

| 入口 | 含义 |
|---|---|
| `scripts/data_pipeline/01_fetch_tushare.py` | 允许核验后的精确供应商响应落盘，持续保留缺口；不是完整抓取成功。 |
| `scripts/daily_update.py` | 日更独立验证限定缺口及真实证据，并把同一参数传给抓取和构建阶段。 |
| `scripts/data_pipeline/05_build_qlib_bins.py` | 构建独立复验清单、覆盖和原始字节证据；保留不完整标记。 |

`--allow-holey-recommend`。后两者不能绕过已有隔离、损坏证据或混合缺口，
也不会自动开启本策略。名称/ST、行情、覆盖、时效及模型等原有检查仍须通过。

## 原始证据和不完整状态

首次隔离前必须有包含全部八个业务键的可信原文件。操作目录中的证据位于
`<原始数据目录>/_suspension_quarantine/<sha256>.parquet`；按内容摘要保存原始
完整参照及每次被替换的保留文件，不覆盖已有证据。当前供应商候选仍写在
`<原始数据目录>/suspend_d.parquet`，只含实际返回并通过检查的行。

`fetch_manifest.json` 记录 `suspend_d` / `file` /
`quarantined_history` 缺口，其 `quarantine` 恰含七项：
`policy_id`、`missing_dates`、`reference_sha256`、`retained_sha256`、
`candidate_sha256`、`query_start_date`、`query_end_date`。
摘要绑定实际文件；后续刷新始终回查原始完整参照，不能拿已经缩短的文件证明恢复。
失败重试保留原隔离并另记普通失败，不能变成“仅有获准缺口”。

数据文件与清单之间使用 `<原始数据目录>/_suspension_quarantine_pending.json`
持久化待完成发布记录。记录存在期间，即便旧清单仍为
v1、清单缺失或开启普通缺口覆盖，构建和普通清单读取都必须拒绝；不能删除记录或
重置清单来解锁。只有显式选择同一策略、包含停复牌端点且范围足够的真实刷新才可
恢复。已完成的双文件提交只清理待完成记录；尚未完成的提交先保存候选字节，再
恢复摘要核实过的旧原件并重新抓取。未知摘要或损坏记录保留现场并拒绝。试运行和
仅刷新其他端点都不执行恢复。恢复全部八键回到 v1 时也遵循相同边界。
候选、日志和清单文件在提交前同步落盘；这是进程中断和写入失败的恢复机制，
并不承诺任意硬件断电下的文件系统事务保证，仍需独立备份和生产验收。

只有携带隔离证据的抓取清单和 provider `_fetch_integrity.json` 使用 schema v2；
干净或普通缺口文档仍为 v1。新读者接受两版但严格核对证据；旧读者拒绝 v2，
不能手改版本来兼容。隔离端点保持 `status="holes"`，数据包保持
`built_from_holey_fetch=true`；结构校验或成功构建都不把它改成完整数据。

抓取正常完成而隔离仍存在时退出 `3`，包括只刷新其他端点仍保留旧隔离的情况；
配置、证据或其他硬错误仍失败。日更仅在显式授权、恰好该一个结构化缺口、
真实证据及其他必需覆盖均合格，且后续重建、验证、切换都成功后，才可退出 `0`。
其完成说明会标注隔离仍有效、数据仍不完整。这是**限定条件下流程完成**，
不是 clean-data 认证；周末无动作的退出 `0` 也不证明发生过刷新。

## 荐股与人工阅读

隔离不影响评分输入或分数，`SH688766` 在最终 Top-K 之前排除，其余候选保持
原分数/顺序并按常规条件补足。若该证券有非 NaN 分数，全量审计仍保留该行，
`tradable_flag=false`、`unavailable_reason="data_quarantine"`；此原因优先于
ST 和不可交易原因，避免重复计数。它不从历史股票池消失，也不表示已有持仓卖出。

- 荐股 JSON 仍为原有 schema v2，`picks` 字段结构不变。活动隔离写入
  `meta.suspension_quarantine`：`policy_id`、`instrument`、
  `built_from_holey_fetch` 和完整 `evidence`；顶层另有 `n_quarantined`。
- 买入候选 CSV 和全量评分 CSV 均追加 `suspension_quarantine_policy`、
  `quarantined_instrument`、`built_from_holey_fetch`、`n_quarantined`。
  空 CSV 仍只有表头、零证券行，实际运行状态须读同名 JSON。
- CLI、今日工作台和每日决策页面明确警告数据不完整、隔离一只证券。即使该证券
  没有进入本次非 NaN 评分，仍显示活动隔离；此时 `n_quarantined=0`，不代表解除。
  UI 的模型来源核验不等于数据完整或历史绩效认证。

`n_quarantined` 是本次实际排除的评分行数，不是活动策略数量。隔离时审计漏斗为
`n_scored + n_masked + n_st_excluded + n_quarantined`，等于非 NaN 评分审计行数。
无活动隔离时不新增隔离专属输出字段。写出器会在任何输出写入前核对隔离元数据、
计数及候选不可泄漏；披露损坏的工件不得作为操作依据。
原有 HOLD/再平衡与已观察交易日限制不变，详见[荐股手册](daily-recommend-runbook.md)。

## 恢复与发布顺序

1. 保留已失败恢复代的文件、清单、日志和摘要；包括既有
   `production_recovery_20260922/full` 证据。不得原地改写失败代来制造成功结果，
   也不得用 `--reset-manifest`、删除参照或手改缺口来断开原证据链。
2. 在新的独立恢复目录、固定代码版本下核验限定继续和默认拒绝两条路径，
   检查原始证据、所有其他覆盖、构建标记、候选排除及 JSON/CSV/UI 提示。
   原始文件已更新但清单尚未成功发布等失败状态须保留检查，不能绕过摘要不符。
3. 真正解除要求供应商重新返回全部八个键、保留所有其他历史并通过原有检查，
   然后成功更新清单并重建数据包。只部分恢复、盲跳过、手动删参数或修改标记
   都不能解除。完整新清单/新包恢复 v1，旧证据仍留存；已选参数对完整包不再
   产生隔离输出，旧导出文件不会被自动改写。
4. 生产另行验收后才安排成套、可回退的发布，先保存最新备份并监督首次日更和
   人工荐股。定时任务最后才可恢复，代码合并不等于恢复调度或完成生产切换。

普通 Pipeline 和 WalkForward 历史训练/回测拒绝隔离包；共享
`BacktestRunner` 的直接调用、`scripts/eval_frozen_model_oos.py` 和
`scripts/retrain_gate.py` 也不能绕过。OOS 评估与重训门禁入口在重计算及结果
输出前拒绝隔离数据。重训门禁仅判定成员/组合的轮换资格，不测量净收益，
不拥有独立绩效权威。任何入口都不把今天的隔离应用到历史股票池，也不重写
既有认证指标。本文仅说明实现边界，**不声明生产数据、首次更新或调度已通过验收**。
