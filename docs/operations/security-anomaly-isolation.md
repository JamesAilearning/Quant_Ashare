# 个股异常隔离与生产恢复

恢复生产优先：能够用原始证据明确归属到个股的数据异常，由维护者自主隔离并推进，不再逐只等待批准。隔离不是删除原始数据、忽略错误、伪造修复或认证历史成绩；异常股在每日荐股 Top-K 之前排除，已有持仓不自动清空、卖出或改写。

## 当前实现范围

`suspend-security-anomalies-v1` 处理完整、合法停复牌响应中实际丢失的历史四字段业务键。候选保持数据源原样，原始/上次文件及必要历史见证不可变留存；名单和日期由真实字节重算，不接受人工填入的豁免名单。同日新增 R/S 或历史回填本身不算异常。

每次最多隔离 10 股，并且严格少于实际保留证据所覆盖证券的一半。查询须覆盖完整证据历史。后续更新只有真正恢复全部相关原始、上次及必要历史见证键，才会解除对应隔离；后来新增的证券或历史记录随后丢失，也不能因再次更新而被遗忘。旧三个事件策略保持原义，不可换 ID 绕过既有隔离或待完成事务。

接口失败、空/截断/畸形响应、非法证券代码、查询范围不足、超出资源/隔离上限、交易日历/全市场错误、其他端点缺口和中断任务仍须停止并保留现场，不能用踢掉股票来掩盖。其他可归属个股的异常遵循同样处置原则，但要先有对应端点的合规检测/证据/隔离契约，不能添加通用捕获报错后继续的路径。

## 操作方式

- CLI 显式传 `--suspension-quarantine suspend-security-anomalies-v1` 给已有更新、构建及荐股入口，保持同一代证据和授权一致。先完成隔离验收，不直接在未备份生产目录试验。
- 页面只查看真实结果与隔离警告；现有手动更新按钮不自动获得该授权，不新增 UI 豁免或历史验证入口。
- 历史回测/成绩认证继续拒绝隔离数据，不能把其他候选可用等同于历史数据完整。

## 避免重复耗时实验

先定位并记录真实进程退出、请求、报告和缺失键，再选最小修复。已成功下载的其他端点数据可在新独立代中做新清单和独立验证后复用，不必重拉所有数据。单独刷新停复牌须真实使用标准获取器并保留其他端点覆盖；随后真实执行构建、数据保真、provider/PIT 和荐股/拒绝边界验收。

失败报告、旧 claim、部分目录不得改成成功或盲目重跑。不能注入假的 fetch 返回值、将诊断候选冒充已完成更新，或用隔离报告冒充生产报告。重任务始终串行、单核/数值库单线程，并保持既定内存监护。

生产恢复还必须具备完整配套回滚备份、可逆切换、固定生产路径验证、首次真实生产更新及验收，最后恢复定时任务。此文和代码通过测试不代表已经生产恢复。
