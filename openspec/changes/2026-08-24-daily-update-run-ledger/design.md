# Design: 运行台账与运行边界

## 写在哪一层

```
run_daily_update            ← 可观测性层：状态工件、边界、台账都在这里
  ├─ 写边界（起）
  ├─ _record_status(running)
  ├─ _execute_daily_update  ← 阶段语义，本改动一个字节不动
  └─ _record_status(finished) → 追加台账
```

新增写入**全部**落在 `run_daily_update`。`_execute_daily_update`（七个阶段、
退出码、fail-loud 通道）不受影响——这既是用户的硬要求，也让「这个改动会不会
弄坏夜间更新」这个问题有一个结构性的答案：它碰不到那条路径。

`--dry-run` 在写状态工件之前就返回，台账与边界同样不写：dry-run 不改变任何
东西，这一条不能因为「只是可观测性」而破例。

CLI 层的退出（配置错误 exit 2、单飞冲突 exit 17）根本不进编排器，因此天然不写
台账——与状态工件那条「被拒的第二次运行不得盖掉持锁那次的记录」同源。

## 反向耦合契约（照抄，不重新发明）

状态工件那条被 codex 加固过的规矩是：**可观测性失败绝不改变退出码**，因此
`_record_status` 吞掉**一切**异常（不只是 `OSError`——`ensure_ascii=False` 遇到
不成对代理会抛 `UnicodeEncodeError`，`json.dumps` 遇到不可序列化值会抛
`TypeError`，任何一个漏网都会反转这条保证），只把缺口记成 ERROR。

台账写入沿用同一条，一字不改。

## 追加纪律（照抄 `decision_journal`）

本仓已有一份被 codex 加固过的 append-only 实现（`decision_journal.append_decision`，
#330 P1）。要点原样搬过来：

- **残尾隔离**：上一个进程若死在写一半、留下一条**没有换行**的尾行，直接追加
  会把新记录焊到那个残片上——一条畸形行，而新记录从历史里静默消失。做法是在
  **同一次** write 里前置一个换行，把残片隔离成它自己那条（被计数的）畸形行。
- **一次 write + flush + fsync**：进程被杀可以丢掉这一行，但绝不能留下半行后面
  再跟一条健康的行。
- 读侧**容错解析**：坏行计数、不让一条坏行毒死整份台账。

## 边界长什么样，以及为什么不多写一个「结束」标记

边界只在**起**的时候写一行，带完整日期时间与 provider：

```
[daily_update] run started <ISO8601 +08:00> provider=<normalized>
```

**不写结束标记**：一段的终点就是下一段的起点或文件尾，切段并不需要它；而
「这次跑完了没有、结果如何」是**状态工件与台账**的职责——再写一个结束标记就是
把同一件事说三遍，而这个仓库反复付学费的正是「一件事写两处」。

带 provider 是照抄状态工件的身份推理（codex #434 r18：每条记录都要指名它描述的
是哪个 provider），这样读侧能拒绝别的 provider 留下的边界。

## 归属能确定到什么程度——以及不能的时候怎么说

日志是无界追加的，而读侧只读**有界**的尾部窗口。于是：

- 窗口里**找得到**边界 → 边界之后的进度行属于该次运行，归属**确定**。
- 窗口里**找不到**边界 → 说明窗口没回溯到那么远。此时如实报「无法归属」——
  也就是**今天的行为**，没有退步。

不去做「窗口不够就再读大一点直到找到」：一次两小时的运行日志无界增长，那条路
通向一个没有上界的读取。宁可在一个说明白的窗口内给确定答案，窗口外老实说不
知道。

## 耗时为什么不落字段

`started_at` 与 `finished_at` 都在台账行里，耗时是它们的差。存第三个字段只是
多造一个会与推导值分叉的地方——本仓刚为「同一件事写两处」连续修了几轮。读侧
推导即可。

## 台账为什么不给 CLI 覆盖

状态工件因为有 `--status-path`，被迫带上一整套路径守卫：改道后的路径若落进
provider / tushare 目录、或别名到退市登记 / 参考用例 / 单飞锁，都要在**任何
写入之前**以配置错误（exit 2）拒绝。

台账路径由 provider 名派生、**没有覆盖开关**，所以操作人无从把它指向别处，那
一整类风险在这里不存在。加一个覆盖开关就等于把那套守卫也一并请进来——收益为
零，面积为正。
