## 4b. codex #475 第二轮：四条 P1/P2

首版的回溯是同一批工件上的**第二条、更弱**的校验路径——页面对**选中**的那份
工件会 `st.stop()` 的形状，回溯却放行并当成可信基准。四条都指向这一点：

- [x] 4b.1 **P1 读不出来的较新工件不能翻过去。** 那一份**本身可能就是一次更近
      的再平衡**；翻过它把更早那张单报成当前基准，就是拿一张**可能已被取代**
      的清单当此刻该持有的。→ 回溯**就地停下**，判为「不可知」
- [x] 4b.2 **这条推广成了整段语义的总闸：只有经过校验的 HOLD 才许可继续往回
      翻。** 它是唯一能证明「那天没换手、所以更早那张单仍然有效」的证据。
      读不出来 / schema 不认 / 日期对不上 / meta 损坏 / 没有节奏字段 / 节奏
      字段形状违约——每一种都让证据链断在这里
- [x] 4b.3 **P1 文件名日期 ↔ payload as_of_date 必须一致。** 改名/拷贝过的
      工件会让「八月三日那一份」其实装着八月十日的截面——拿它当基准就是把
      **未来数据**当成当日应持有。选中工件流早有这道闸（`daily_decision.py`
      的日期一致性闸），回溯此前没有
- [x] 4b.4 **P1 带 v2 标记却没有 dict meta 的工件必须拒绝。** 产出器对 v2 恒
      写 dict meta，选中工件流对同一形状 `st.stop()`，回溯此前放行
- [x] 4b.5 **P2 损坏的名单不是空名单。** 首版 `except ValueError: roster = ()`
      之后页面接着说「名义上跟的是 X 那次的清单（共 **0** 只）」——把一份损坏
      工件渲染成一个**合法的空仓位**，而这一页别处对 picks 形状违约的处置正是
      「要被看见，不要被渲染成良性空缺」。→ 整段改判不可用
- [x] 4b.6 页面从两态改成**三态互斥**：找到 / **不可知**（回溯停在哪一份、
      因为什么）/ 翻完了都没有。「不知道」与「确实没有」对操作人的下一步完全
      不同
- [x] 4b.7 本机真实工件复跑：结论从「翻完了、没找到」变成
      **「不可知：回溯在 2026-06-16 停下——schema 不受支持」**。严格更诚实——
      我们并**没有**翻完，是证据链断了
- [x] 4b.8 变异复验 **21 条全咬住**（新增：阻断条件熄火 / 读不出来被翻过去 /
      四道新闸各熄火 / 损坏名单退成空名单 / 不可知与翻完了混成一句）

- [x] 缺口报**区间端点**而不是前三天:操作人要判断的是「缺的这一段跨没跨过

## 4e. 自查审计（多智能体，非评审提出）：清单长度的恒等式没人执法

第三轮把整类形状闸下沉之后，我跑了一轮**跨工件族的读侧-产出器契约比对**
（五个族并行枚举 + 逐条对抗式反驳，35 个 agent，16 条确认 / 14 条被驳回）。
与本 change 直接相关的三条都在**我刚建的那道共用闸**里：

- [x] **`len(picks) == min(n_scored, meta.topk)` 无人执法**（两个独立 agent
      各自发现，均通过对抗反驳）。产出器的 picks 是可交易池按分降序的
      `head(topk)`，而 `n_scored` 就是那个池子的大小，所以这个等式是**构造
      上**定死的。此前只验了上界那一半 ⇒ 一份 50 条的合法工件删到 3 条，
      rank 仍连续、分仍降序、代码仍唯一、行日期仍对得上——所有闸都放行，
      头卡会说「有再平衡指令 · 共 3 只候选」；**删光**则翻成「不动 · 目标
      清单为空」，在一个真实的再平衡日上告诉操作人不必动作
- [x] **三个计数字段（`n_scored` / `n_masked` / `n_st_excluded`）此前无任何
      reader 验过**。必须先验（非负 int）再算恒等式——否则新闸自己会被一个
      字符串或负数绕过；而后两个是详情页 caption 上「宇宙被筛掉多少」的
      依据，一个负数会被原样端给操作人当统计口径
- [x] **带首尾空白的 stock_code 要拒，不要 strip 后放行**。重复码闸逐字节
      比，而同页更靠后的人工审阅助手 strip 后再比——`" SH600000"` 与
      `"SH600000"` 会同时通过重复码闸，于是同一份工件在同一页上给出两个
      互相矛盾的结论
- [x] 超出上界仍报**「超出 meta.topk」**这句，不退回笼统的恒等式句:两句话
      对操作人的下一步不同。不钉这句，把上界那道闸整条删掉都不会红（变异
      实测逃逸，已补钉）
- [x] 变异复验 **45/45**。首轮逃 2 条:上界闸（被恒等式数值蕴含 → 补钉成因
      句）、`stock_code` 在场闸（新加的空白闸对空串恒 False → 补一条空/缺
      /非串的用例）
- [x] **两处夹具又缺了产出器恒写的字段**（三个计数）——这是本 PR 第三次
      栽在同一形状上。补上，并让夹具满足恒等式（`_set_picks` 改 picks 时
      连带拨 `n_scored`）
- [x] 真实工件复核不变式:`2026-07-31` 的 `n_scored=800 / topk=50 /
      len(picks)=50`，`min(800,50)==50` ✓；两份工件的行键都恰是那八个；
      无一个代码带空白
- [x] `tests/logic` + `tests/governance` **5096 passed**
