## 4b. codex #475 第二轮：四条 P1/P2

首版的回溯是同一批工件上的**第二条、更弱**的校验路径——页面对**选中**的那份
工件会 `st.stop()` 的形状，回溯却放行并当成可信基准。四条都指向这一点：

- [x] 4b.1 **P1 读不出来的较新工件不能翻过去。** 那一份**本身可能就是一次更近
      的再平衡**；翻过它把更早那张单报成当前基准，就是拿一张**可能已被取代**
      的清单当此刻该持有的。→ 回溯**就地停下**，判为「不可知」
- [x] 4b.2 **这条推广成了整段语义的总闸：只有经过校验的 HOLD 才许可继续往回
      翻。** 它是唯一能证明「那天没换手、所以更早那张单仍然有效」的证据。
      读不出来 / schema 不认 / 日期对不上 / meta 损坏 / 没有节奏字段 / 节奏
      字段形状违约——每一种都让证据链断在这里
- [x] 4b.3 **P1 文件名日期 ↔ payload as_of_date 必须一致。** 改名/拷贝过的
      工件会让「八月三日那一份」其实装着八月十日的截面——拿它当基准就是把
      **未来数据**当成当日应持有。选中工件流早有这道闸（`daily_decision.py`
      的日期一致性闸），回溯此前没有
- [x] 4b.4 **P1 带 v2 标记却没有 dict meta 的工件必须拒绝。** 产出器对 v2 恒
      写 dict meta，选中工件流对同一形状 `st.stop()`，回溯此前放行
- [x] 4b.5 **P2 损坏的名单不是空名单。** 首版 `except ValueError: roster = ()`
      之后页面接着说「名义上跟的是 X 那次的清单（共 **0** 只）」——把一份损坏
      工件渲染成一个**合法的空仓位**，而这一页别处对 picks 形状违约的处置正是
      「要被看见，不要被渲染成良性空缺」。→ 整段改判不可用
- [x] 4b.6 页面从两态改成**三态互斥**：找到 / **不可知**（回溯停在哪一份、
      因为什么）/ 翻完了都没有。「不知道」与「确实没有」对操作人的下一步完全
      不同
- [x] 4b.7 本机真实工件复跑：结论从「翻完了、没找到」变成
      **「不可知：回溯在 2026-06-16 停下——schema 不受支持」**。严格更诚实——
      我们并**没有**翻完，是证据链断了
- [x] 4b.8 变异复验 **21 条全咬住**（新增：阻断条件熄火 / 读不出来被翻过去 /
      四道新闸各熄火 / 损坏名单退成空名单 / 不可知与翻完了混成一句）
