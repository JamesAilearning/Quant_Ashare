- [x] 判据两侧都 resolve：跨得过链接/联接/8.3 短名
- [x] 不满足时 warning + 跳过（与既有 `OSError` 契约一致），并说清原因
- [x] 维护脚本：默认只报数，`--prune` 才动手，移除行原样写旁车文件留证

- [x] 脚本 `--tree` 显式指定边界并打印出来

- [x] 相对 `output_dir` 按**生产者的 CWD** 解析（两侧读法一致时存的字符串不变）
- [x] 两种读法分歧时改存绝对路径，记录不指向不存在的目录
- [x] 写入侧与清理脚本共用跨进程劝告锁；脚本在**锁内**重新分类

- [x] 脚本拿不到锁返回 4、什么都不动；锁内仍被改动返回 3、连旁车一并撤掉
- [x] 相对路径的锚**独立点名**（`--relative-base`），绝不从 `--tree` 反推

```

守卫 13 → 20 条。变异复核（每条先断言变异确实落进文件，再看红）
  A 判据退回纯词法(不 resolve)            抓到  1 failed, 19 passed
  B 去掉 isinstance(record, dict)         抓到  1 failed, 19 passed
  C 去掉改写前的指纹比对                  抓到  1 failed, 19 passed
  D 旁车不再先写                          抓到  7 failed, 13 passed
  E 相对路径退回按仓库根解析              抓到  2 failed, 18 passed
  F 分歧时不改存绝对路径                  抓到  1 failed, 19 passed
  G 锁变成永远成功(等于没锁)              抓到  2 failed, 18 passed
  H 指纹取样挪到分类之后                  抓到  1 failed, 19 passed
  I 抹掉 fallback-ok 标记                 守卫抓到
```

`test_no_silent_fallbacks` 抓到锁里 `except` 的裸 `yield False` —— 用带署名
理由的 `# fallback-ok:` 标记（标记必须挂在 `except` 那一行本身），并变异验证
抹掉标记会重新变红。

**残余风险**（第三轮时如此写，第四轮已消除，留档见证）：写入侧曾在等锁 5 秒
超时后绕过锁照样写。codex 指出「锁内起点指纹 vs 替换前指纹」兜不住它 —— 无锁
追加可以落在最后一次指纹之后、`os.replace` 之前，任何检查都看不见。那条刻意的
绕过路径正是窗口的唯一来源，取消它窗口才真的关上。
