# 运行目录索引：默认路径按 CWD 解析，测试把记录写进操作人的真实索引

## 问题（实测，数字原样）

`src/core/run_catalog.py:20`

```python
_DEFAULT_CATALOG_PATH = Path("output/runs/_index.jsonl")
```

**相对路径 = 按进程 CWD 解析**。两个生产调用点（`pipeline.py:861`、
`walk_forward/engine.py:528`）都不传 `catalog_path`，测试也从不传。于是
pytest 从仓库根跑时，每一次触发引擎的测试都往**操作人的真实索引**追加一行，
而它的产物在临时目录里、随后被删。

本机实测：

```
索引总行数                3560
产物在 output 树内          105  =  2.9%
产物在树外（= 污染）       3455  = 97.1%
   系统 Temp 目录          2279
   4 个硬编码测试夹具路径  1176   （\tmp\wf_test_irrelevant 等各 294 次）
```

**污染是活的，不是历史遗留**：本会话开始时是 3527 行，我跑了几轮全量测试之后
变成 3560 —— **多出来的 33 行就是我自己跑测试写进去的**。

树内 105 行的产物目录 **105/105 仍在盘上**；树外行里抽样 400 条只有 78 条目录
还在，且那 78 条全是 `\tmp\wf_test_*` 那四个夹具目录。**没有发现任何合法的
「产物落在 output 树外」的工作流。**

## 后果

- 作业页每次渲染都要对 3560 行做可检视过滤，其中 97% 注定被搁置；披露行数
  常年是个大数字，真实历史被淹没在噪音里。
- 索引是 run comparison 的输入。一份 97% 是残骸的索引，任何「历史上跑过什么」
  的查询都要先自己去噪。

## 根因

两个独立缺陷叠在一起：

1. **默认路径按 CWD 解析** —— 同一份代码从不同目录启动会写到不同文件，
   这与 #444 修过的 `run_dir_is_inspectable` 锚定问题是同一类。
2. **写入侧没有边界判据** —— 产物落在 output 树外的运行，操作人**永远打不开**
   （那正是 #444 钉死的读边界），却照样进索引。

## 方案

1. 默认索引路径**锚在仓库根**，不再随 CWD 变。
2. `append_run_record` 走**默认索引**时，追加前检查记录的 `output_dir` 是否
   落在仓库那棵 output 树内；不在则**大声跳过**（warning + 原因），不写。
   - 边界是**具名的**（`<repo>/output`），不从索引文件位置反推。
   - 跳过而非抛错：与本函数既有契约一致（`OSError` 时也是 warning + 继续，
     「产物仍在运行目录里」）。编目是旁路记录，不是运行的产物。
   - 显式传 `catalog_path` = 逃生口，不设边界（污染走的是无参默认路径）。
3. 判据**两侧都 resolve**，跨得过链接/联接/8.3 短名；清理脚本与写入侧**共用
   同一个函数**。

## 第二轮修正（codex 四条 + CI 实测）

首版有两个真缺陷，都由「把索引文件位置当判据」引出：

- **从 `<tree>/runs/<file>` 反推边界** —— `/tmp/catalog.jsonl` 推出 `/`，于是
  接受一切绝对路径；`<repo>/output/custom.jsonl` 推出 `<repo>`，于是接受
  output 树外的运行。文件摆放位置成了隐藏的安全契约。改为具名边界后，这条
  连同「相对索引位置」的说法一起撤销。
- **纯词法比对** —— `output/` 是链接时，或树是长名而运行目录是短名时，
  **每一次合法运行都被拒**。这不是假想：GitHub 的 Windows runner 把 `TEMP`
  设成 `C:/Users/RUNNER~1/...`，首版把三个 Windows 位全打红了。
  #444 在控制台读边界上栽过同一个坑，教训没带过来。

清理脚本另修两条：分类与改写之间被并发追加的行会永久丢失（改为指纹比对 +
不一致就拒绝动手 + 原子替换）；`null` 这类合法但非记录的 JSON 会让只报数模式
抛 `AttributeError` 中断（改为保留）。

## 清理已有的 3455 行：**不在本 PR 里动**

那是操作人的真实数据文件。本 PR 只提供一个**只读报告 + 显式开关**的维护脚本：
默认只报数、`--prune` 才动手，且被移除的行**原样写入旁车文件**留证，绝不静默
删除。由操作人自己跑、自己签收。

## 影响面

- `src/core/run_catalog.py`（写入侧）
- 无既有测试断言 `append_run_record` 的路径行为（只有 `build_record` 的 schema
  测试），因此不改任何现有断言。
