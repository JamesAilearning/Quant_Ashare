# Proposal: 决策①修订 — 基线起点退至 2015-10-01，IS 窗全覆盖

**本提案修订一项已签署的预注册决策**（决策①，2026-08-05 随
`docs/prereg/pv_incremental.yaml` 冻结，台账 E001 `semantics_pinned`
登记）。修订需操作人重新签字；签署前本提案与配套 PR 一律不合。

codex #411 r1 抓到原 PR 试图在不重签的情况下改掉该决策——这是对的。
本提案就是那次被拒后的正规通道。

## 原决策与其理由

决策①（`is_coverage_policy: penalize_covered_days_only` 的冻结注文）：

> 基线保持生产 walk-forward 折几何，首个样本外日晚于 IS 窗起点，故
> IS 前段无基线可比。正交罚只在有基线覆盖的日子计算；无重叠表达式
> 不罚，但覆盖计数入 run 记录如实披露（**不缩短 train 窗造"更早基
> 线"——那不是生产模型族**）。

签署时的约束是**数据边界**：qlib bundle 起于 2018-01-02。当时"更早的
基线"只能靠缩短 train 窗伪造，那确实不是生产模型族——原决策在当时的
数据下是唯一诚实的选择。

## 变了什么

数据边界解除了（2026-08-08）：

- tushare 回补 2015-10-01..2017-12-31：52,866 单元、零 hole；
- 独立审计六道全过，含随机抽样**实调 API 逐值比对 0 处不符**；
- namechange 补全（4,732 → 14,165 行，2015-2017 段 0 → 4,076 条，
  ST 掩码在该段因此可用）；
- 新 bundle `my_cn_data_pit_2015`：日历 2,082 → 2,631 天，新增 549
  天恰等于该区间交易日数（与 trade_cal 独立互证）；生产 bundle
  `my_cn_data_pit` 未触碰（首日仍 2018-01-02）。

## 修订内容

`config/presets/pv_incremental_baseline.yaml` 增
`overall_start: "2015-10-01"`（父配置默认 2018-01-01）。

**不变**：train 24m / valid 3m / test 3m / step 3m、ensemble_window 3、
model、universe、overall_end 2024-12-31（圣规防线）、
`is_coverage_policy` 机制本身（正交罚仍只在有覆盖的日子计算——修订后
覆盖恰好是全部 IS 日）。

## 为什么这仍是"生产模型族"

原决策禁止的是**缩短 train 窗**伪造更早基线。本修订 train 窗仍是
24m——改的只是同一折几何在时间轴上的起点。且 27 个月恰为 step(3) 的
整数倍，**折网格完全对齐**：

- 原 19 折的 test 窗**原样保留**，仅前置 9 个新折（2018Q1..2020Q1）；
- **OOS（2023-2024）的 8 个折分毫不动**——FWER 判据一侧完全不受本修
  订影响；
- 每折的训练数据窗跨入 2015-2017 段，该段数据与 2018+ 同源（同
  fetcher、同审计标准、同 PIT 构建器）。

修订后首个 test 窗 = 2018-01-01 = 冻结 IS 起点：正交罚从"55% 的 IS
日有约束"变为"100%"。

## 语义变更的如实陈述

修订**确实改变**繁殖环境：GP 候选在 2018-01..2020-03 段将面对
"有基线可比"而非"无罚通过"。这正是修订目的——原状态下候选可以在
45% 的 IS 日上与基线任意相关而不受罚。

已产生的工件中无一依赖旧覆盖语义：首跑基线因 3 折失败已废弃，重跑
基线（2026-08-08 导出）随本修订一并作废重跑。GP 批次尚未点火，OOS
评估尚未发生——**修订发生在任何候选被评估之前**，无回溯改判。
