## 5c. 独立对抗审查（我自己起的，非评审意见）

四个 PR 各派一名独立审查 + 逐条对抗证伪，本 PR 得到 **6 条确认成立**（另有
数条被证伪的未采纳）。全部已修：

- [x] 5c.1 **结果页的篮子排在自动刷新的 `st.rerun()` 之后 ⇒ 运行中的作业
      勾了自动刷新就永远画不到篮子。** 那个 `st.rerun()` 抛 RerunException
      立刻终止本帧；加入按钮没了，从别的页攒进去的篮子也整个消失，操作人
      会以为篮子丢了。而「运行中」正是这一页最常驻留的状态（页面自己的注释
      写着典型 pipeline 跑 1-8 小时）。→ 篮子移到选中运行之后的**第一件事**
- [x] 5c.2 **作业页的篮子面板挂在「选中某一行」之内 ⇒ 默认态下整个篮子
      不可见。** 那张表 `on_select="rerun"` 且默认无选中行；操作人从别的页
      攒好切过来看到的是「篮子不见了」，随便点中任意一行它才回来。→ 移到
      选中块之外，无选中行时走 `render_standalone_basket`（空篮子不读盘）
- [x] 5c.3 **「已在篮子里」拿新解析的 id 比旧存的 id** ⇒ 目录归属变化后
      同一次运行能被加进去两次，复核时坍塌成同一所有者、链接被重复检查
      挡住，而操作人看到两行不同的 id。→ 篮子也按当前目录解析一遍再比
- [x] 5c.4 **来源页交出的 id 与目录所有者不在同一命名空间时，理由是假的。**
      成因是同一次运行的 UI 作业与 CLI 目录记录之间镜像证明不成立（时间线
      /生产者字段任一不满足），那是**同一份产物的两条记录**，不是「被一次
      更新的运行接管」。→ 说出目录里代表它的那个 id；同目录找不到代表时
      **不猜原因**（那一格按 `selectable_catalog` 的构造不该出现，出现即
      输入不自洽）
- [x] 5c.5 **`revalidate_basket` 对 `selectable_ids` / `all_rows` 逐成员
      重复消费** ⇒ 传一次性迭代器时第一个成员就把它抽干，之后全部误判为
      失效。类型标注 `Iterable` 反而给这个不成立的契约背了书。→ 进循环前
      物化一次
- [x] 5c.6 **失效成员的总标题把一种原因说成全部**（「加入之后目录归属变
      了」），而 stale 里有五种 verdict，紧跟的逐条说明会与它直接打架。→
      总标题只报数，原因交给逐条
- [x] 5c.7 变异复验扩到 **47 条全咬住**（新增八条，含「篮子挪到自动刷新
      之后」「面板缩回选中块之内」「already 比生篮子」「一次性迭代器」
      「总标题替五种原因下同一个结论」「拿别的目录的记录冒充同目录所有者」）

## 6. 划界（本 change 不做）

- 不判可比性：那是对比页 `assess_comparability` 的事，入口重推必然漂移。
- 篮子不跨会话持久化：它是「我现在想比这几个」的临时意图，不是需要留档的
  研究决定。
- 不做批量加入（「把这一页筛选结果全加进来」）：上界是 5，批量只会把篮子
  一次填满并逼出「先移除一个」。

## 5d. codex #472 第三轮

- [x] 5d.1 **P2 同目录所有者必须按运行类型匹配。** `selectable_catalog` 的所有权
      是按 `(类型, 目录)` 定的；只按目录匹配会把一条旧 pipeline 记录说成「由某个
      walk_forward id 代表」，而那个 id 根本不是它那一组的所有者
- [x] 5d.2 **P2 「被接管」与「同一份产物的两条记录」是两种成因，不能用同一句。**
      上一轮我把一句假话换成了另一句假话：两次**独立**的同类型运行复用同一个
      output_dir 时，「同一份产物的另一条记录」就是错的。现在按实据分三档——
      来源相同 ⇒ 真接管；来源不同且任一方**生产者记录**了对方 id ⇒ 同一次运行的
      两条记录、镜像证明不成立；来源不同又无生产者关系 ⇒ **不猜**，只说目录里
      由谁代表
- [x] 5d.3 断言改钉「镜像证明不成立」这句**独有**措辞：首版钉「同一次运行」，
      而中立那句里的「无法判断它们是同一次运行还是先后两次」也含这四个字，
      两条分支都通过（变异实测逃逸）
- [x] 5d.4 变异复验 **49 条全咬住**（新增：所有者不按类型匹配 / 真接管被说成
      另一条记录 / 镜像证明不成立被说成无法判断 / 无生产者关系也断言同一次运行）
