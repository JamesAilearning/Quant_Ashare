# 工作台不回答操作人每天真正的问题：「今天到底要不要买」

## Why

操作人的原话：每天打开系统，最想知道的一件事是**今天有没有买入信号**。
现状要自己拼三块才能得出答案：数据健康卡（陈旧了信号不可信）、日度信号卡
（HOLD 还是再平衡）、还得自己想「这份工件是不是说给今天的」。三块都在页
上，结论没人合成——P0 缺口（UI 评估已批序列④）。

## What Changes

- 工作台顶部新增「今天要不要买」合成句卡，三态 + 如实边缘：
  - **有买入指令（待人工核对）**：已核验来源的再平衡工件、执行日 = 今天；
  - **不买 · 观察日**：HOLD 工件、执行日 = 今天，点名下一再平衡日；
  - **无法给出**：出单侧判据拒绝（陈旧/完整性/裁决不可达）或工件需核查，
    带原因与数字；
  - **没有面向今天的指令**：尚无工件，或最新指令的执行日不是今天——如实
    点名那个日期（流程态，不是错误态）。
- 每一态都带「不是订单、不授予交易许可」免责声明。

## 本 change **不新造**任何判定

陈旧与完整性用出单侧自己的裁决（`bundle_freshness` /
`recommender_integrity_check`，今日待办队列同款消费面）；节奏用
`summarise_daily_signal` 已核验来源的分类；「说给今天」只看
`entry_date == cn_today()`（出单协议：entry 是收盘后生成、面向下一交易日
的执行日）。合成层只做措辞与优先级——出单侧判据先行：出单侧今天会拒时，
即使手上有一份看起来是今天的指令也拒答（该组合正常流程到不了，真到了说明
有一侧在说谎，拒答比选边站诚实）。

## Non-goals

- 不生成订单、不计算差分、不接收持仓输入（P2 护栏预留，与本卡无关）。
- 不改任何既有卡片与队列语义——合成句是新增的第一视图，不替代详情核对。
