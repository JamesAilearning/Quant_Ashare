# 工作台不回答操作人每天真正的问题：「今天到底要不要买」

## Why

操作人的原话：每天打开系统，最想知道的一件事是**今天有没有买入信号**。
现状要自己拼三块才能得出答案：数据健康卡（陈旧了信号不可信）、日度信号卡
（HOLD 还是再平衡）、还得自己想「这份工件是不是最新的」。三块都在页上，
结论没人合成——P0 缺口（UI 评估已批序列④）。

## What Changes

- 工作台顶部新增「今天要不要买」合成句卡，四态：
  - **有再平衡指令（待人工核对）**：已核验来源、清单非空、`entry_date`
    与出单侧日历尾对上（= 数据所及的最新指令）；点名候选数与已收盘披露；
  - **不动**：最新指令为 HOLD（点名下一再平衡日），或再平衡清单为空
    （`--topk 0` / 全部候选被掩蔽是合法产出）；
  - **没有可执行的指令**（流程态）：尚无工件，或数据尾已走到最新指令之后
    （出单没跟上）——两个日期如实点名，指向运行中心；
  - **无法给出**（异常态）：出单侧判据拒绝（陈旧/完整性/健康份额/裁决不可
    达）、工件需核查、或工件声称的会话晚于数据尾——带原因与数字。
- 每一态都带「不是订单、不授予交易许可」免责声明。

## 本 change **不新造**任何判定、不引入任何时钟

数据包前置用出单侧自己的 `usable` 判据**全额**消费（年龄 + 完整性 + 健康
摘要「只扣分」的份额）；节奏与候选**基数**用 `summarise_daily_signal` 已
核验来源的分类；「指令新不新」= `entry_date` 对出单侧日历尾——出单器就是
从那份 bundle 跑的，不比挂钟。

**entry 语义遵守既有基线**（v2-daily-decision-page）：`entry_date` 是
**已收盘会话**，清单不是「明早买入」指令，真实订单如何向清单收敛是操作人
的执行惯例（观察期记录的正是该偏差）。本卡不给任何执行时点，只说清「最新
指令是什么」；出单侧判据先行——会拒时即使工件对得上数据尾也拒答。

## Non-goals

- 不生成订单、不计算差分、不接收持仓输入（P2 护栏预留，与本卡无关）。
- 不改任何既有卡片与队列语义——合成句是新增的第一视图，不替代详情核对。
