## codex 第十九轮：两个 P2 —— 第二种 shell 的形状、wrapper 解包

**Windows 腿默认跑 pwsh**（test.yml 无 shell: 覆盖）——`$env:PIP_DRY_RUN=1`
在那里与 export 等效。形状正则并入 PowerShell 拼写（`$env:PIP_*` /
`Env:PIP_*`，Set-Item 的路径实参），仍是认形状不认载体。**边界如实记录**：
词法器建模的是 POSIX，pwsh 全文法不建模；若后续意见要求整体 shell-aware，
届时呈裁决。

**`env pip install …` / `command pip install …` 是真安装。** 第 0 个 token
是 wrapper 时整条安装从三处覆盖面同时消失（这次是漏报方向）。解包这两个
POSIX 定义的「运行后面那条命令」实用程序：env 的赋值前缀并入环境检查，
wrapper 的裸选项（可能吃值）多义即响亮。不做开放枚举，新 wrapper 由底数
断言暴露。

## codex 第十八轮：一个 P1 + 一个 P2 —— 载体不枚举，认形状；大小写不敏感

**P1 `export PIP_DRY_RUN=1; pip install …`**：赋值坐在另一条命令里、随后
持续生效，行内前缀检查看不见。修法不枚举载体（export/env/set/…），认
**token 形状**：`PIP_*=` 无论坐在哪条命令里，唯一的作用就是配置 pip——
全命令扫描，命中即响亮。**P2 大小写**：Windows 腿环境名大小写不敏感，
`pip_dry_run=1` 与 `PIP_DRY_RUN=1` 等效——形状正则与三层 env 键检查都改
大小写不敏感。

**变异揭出两条守卫在干净数据上空转**（BO/BQ：真实 workflow 没有违例 token，
负断言测不出扫描被删）——按本 PR 既立的**两层作证**模式收：把扫描抽成
helper（`_pip_environment_offenders` / `_pip_env_key_offenders`），真数据
守卫消费 helper 且只留底数断言，合成数据直接单测 helper。复验三条全咬。

## codex 第十七轮：一个 P1 + 一个 P2 —— env 的三层注入面、附着式短选项

**P1 workflow `env:` 也能配置 pip。** GitHub Actions 把 workflow/job/step
三层 env 施加到 run 命令上——`env: {PIP_DRY_RUN: "1"}` 让步骤里的安装什么都
不装，run 文本毫无痕迹。`_environment_keys` 收齐三层键，任何 `PIP_*` 键即
响亮；底数断言钉住收集真的读到了现有声明（RUN_E2E ×N、REASON），单元用例
钉三层全见。

**P2 附着式短选项值。** optparse 允许 `-rrequirements.txt`——只认精确
`-r` 与 `=` 连写，这种形态落进无条件 continue。顺手把同一条规则下的
`-e.[research]` 一起收（目标候选），不留给下一轮。

## codex 第十六轮：一个 P1 —— pip 行为可经环境注入

`PIP_DRY_RUN=1 pip install <窗口> <qlib pin>`：pip 把每个选项都映射成
`PIP_<OPTION>` 环境变量，赋值前缀被剥掉丢弃后，安装与窗口两道守卫全过而
pip 什么都不装。分辨哪些 PIP_* 改行为又要查 pip 的选项表——不维护，**多义
即响亮**：pip 命令上任何 `PIP_*` 赋值一律拒，药方是改写成显式 flag（flag 受
--dry-run / 文件引入等既有判据管辖）。此前当反例用的 PIP_NO_CACHE_DIR 一视
同仁翻面。非 PIP_ 赋值照常放行。

## codex 第十五轮：三个 P2 —— 文件引入、可变引用、= 连写的目标

**`-r/--requirement`（及 `-c/--constraint`）从文件引入安装内容。** 命令文本
推导看不见文件里的每一行——静默跳过选项 = 覆盖面在整个文件上空着。响亮拒，
药方是把 requirement 内联。

**qlib 的 `@` 后缀必须是不可变 commit。** 只看 URL 前缀，`@main` 也算
「钉住」——CI 的 qlib 代码在两次运行之间漂移而守卫全绿。校验完整 40 位
十六进制 SHA。

**`--editable=.[research]` 的目标藏在 `=` 后面。** 只看裸 token，extra 连同
无上界依赖静默脱离覆盖面，可解析性检查也跳过它。目标候选统一经
`_local_target_candidates`（裸 token + `--editable=` 的值），两处消费同源。

## codex 第十四轮：三个 P2 —— 词法器的三处精度

**终止行要精确匹配。** `  EOF` 在 shell 眼里是正文，`strip()` 把它当收尾，
其后的真正文被读成命令——发明覆盖面或误报红。终止行精确相等；`<<-` 形态由
语法自己给出唯一例外：只剥前导 tab。

**定界词要做真·引号移除。** `E'O'F` 的生效定界词是 `EOF`，只剥两端会存成
`E'O'F`、真收尾永远配不上、workflow 被误判未收尾；反斜杠也是引号（`<<` 后接
反斜杠的定界词=字面量正文），只认引号字符会把它当活性正文误拒。构件与词法器
主循环同一套：单引号、双引号、反斜杠。

**重述检测要认 extras 段。** `numpy[feature]>=1.24,<2.1` 也是 numpy 窗口的
重述，「名字后必须紧跟版本运算符」让它带着分叉窗口整条躲过。跳过 `[...]` 再
看运算符；逐字断言自然把非规范形态打红。

## codex 第十三轮：两个 P1 —— 覆盖面对 pip 自己是盲的、dry-run 不装东西

**P1 pip 引导无上界。** 两条 workflow 都跑 `python -m pip install --upgrade
pip`——pip 是解析安装一切的那个工具，一次新版能改变全部 CI 安装的结果，而
覆盖面只走 pyproject 三处 + extras，对「workflow 直接装的包」是盲的，与
不变式正面矛盾。修两处：workflow 引导钉窗（`pip>=24,<26`，与 setuptools
同类的宽上界）；新守卫 `_direct_install_targets` 把直接目标全数纳管——
requirement 形状的要上界、未钉 commit 的 git+ 点名、无法归类的（多半是接值
裸选项的值）响亮并给出 --opt=value 药方。变异 AU 证明守卫真的盯着 workflow：
把引导改回无上界当场红。

**P1 `--dry-run` 不装东西。** pip 自己定义它「Don't actually install
anything」——带着它的 `pip install <窗口> <qlib pin>` 能同时骗过「是安装」
「带齐窗口」两道守卫，而 qlib 缺席、`importorskip` 让 CI 静默绿。子命令对了
仍不等于装了；`--dry-run` 在场即不算安装。

## codex 第十二轮：一个 P1 + 一个 P2 —— URL 不是安装，实参不是子命令

**P1 qlib pin 检查只认 URL。** 一条 `echo git+…qlib… "numpy…"` 也满足两条
断言——真安装被误删只剩回显时守卫照样绿，而 `pytest.importorskip("qlib")`
会让 qlib 侧 CI 静默跳过。候选先过 `_is_pip_install`（新 helper
`_qlib_pin_installs`，可单测可变异）。

**P2 `install` 必须是子命令。** `pip --help install ".[research]"` 只打印
帮助，在实参里搜 `install` 会把 research 记进覆盖面、治理误报红。三条判据
都不需要 pip 的选项表：帮助 flag 优先（argparse 通例）；子命令 = 可执行体后
第一个不带 `-` 的 token；子命令前的**裸**选项（可能接值）多义即响亮，
`--opt=value` 连写自含值不拦。

## codex 第十一轮：两个 P2 —— 未引号 heredoc 的活性体、选项值的歧义

**未加引号的定界词让 heredoc 正文保持活性。** POSIX 在这种正文里做命令替换，
`cat <<EOF` 正文里的 `$(pip install …)` 真的会执行——而词法器无条件丢弃全部
正文。修法：定界词带引号（字面量正文）照旧跳过；未引号正文含 `$(`/反引号
即响亮拒读（`$VAR` 变量展开执行不了命令，不拦）。

**选项值与安装目标无法不带选项表地区分。** `pip install --find-links .
".[research]"` 里 `.` 与 `.[research]` 都长得像本地目标，取第一个会把 extras
静默丢掉。pip 的选项表随版本变、不该由本守卫维护——**多候选即响亮**
（AmbiguousPipCommand），要求 `--opt=value` 连写形态消歧（值不再是独立
token，歧义就地消失）。

## codex 第十轮：两个 P2 —— 引号内续行、$( 的两难收成同一原则

**双引号内的 `\<换行>` 也是续行。** shell 在分词前删掉它，`".[dev,\` 换行
`ui]"` 执行时就是 `.[dev,ui]`；保留原样，比对拿着一个执行时不存在的反斜杠
换行——要么发明未声明的 extra，要么把逐字一致的重述拒掉。归一化在扫描时做；
转义反斜杠后跟的**真**换行不动（有反面用例钉着）。

**`$()` 与外层命令纠缠。** `echo $(date) pip install …` 里只有 `date` 与外层
`echo` 会执行——把括号当无条件边界会**发明**一条 shell 根本不跑的
`pip install`，治理对 CI 没装的依赖变红。上一轮删掉 `$(` 分支时的变异结论
（「裸括号规则已覆盖」）只对当时的测试面成立，语义上是错的。建模嵌套重挂是
shell 全文法的无底洞——与引号内替换**同一处置：响亮拒读**（仓库零使用，
workflows-all-lex 守卫兜底）。裸 `(cmd)` 子 shell 保持边界拆分：POSIX 语法里
`)` 之后同一条命令不能再接词，安全。

## codex 第九轮：三个 P2 —— 活性内容、保留字、规范名

**双引号里的 `$(`/反引号是活性的。** shell 会执行它，而词法器把整段引号当成
不透明词，里面的安装静默消失。**不去建模引号内替换**（嵌套引号、嵌套替换、
参数展开——shell 全文法的无底洞），改用本 PR 立下的既有原则收口：**响亮
拒读**。「现有 workflow 全部可词法化」的守卫保证仓库不用这种写法；未来谁要
用，治理红着告诉作者去改写。未加引号的反引号（遗留命令替换）同类处理。

**`if pip install …; then` 的可执行体是 `pip`。** 保留字引导复合命令；只认
第 0 个 token，条件化安装整条消失。保留字是 POSIX.1-2017 §2.4 定义的闭集，
剥完保留字再剥赋值前缀，然后才是可执行体。

**包名按 PEP 503 归一化比较。** `NumPy>=1.24,<2.1` 也是 numpy 窗口的重述，
大小写敏感的 `startswith` 让它带着分叉上界整条躲过。检测按归一名，逐字断言
仍比原 token——非规范拼写会被要求改写，不是被放过。

## codex 第八轮：两个 P2 —— 位置与语法，误报与漏报同罪

**`pip` 是位置，不是子串。** 上一轮按可执行体命名认 pip，但在**实参里扫**：
一条 `echo pip install -e ".[research]"`（打日志的示例）会被当成真安装，
research 组那些刻意无上界的依赖就把治理打红——而 CI 根本没装它们。误报与
漏报同样是错的。改为认**可执行体的位置**：跳过 POSIX 赋值前缀后的第一个
token（`python -m pip` 模块形态单列）。

**未加引号的 `(`/`)` 是命令语法。** `(pip install …)` 合法，括号焊在 token 上
让 `_is_pip_install` 与 `_local_target` 都认不出。词法器补上这一构件；单列过
一个 `$(` 分支，变异证明它是死代码（裸括号规则已覆盖）——删。

## codex 第七轮：一个 P2 + 一个 P1（记录层）

**P2 只认字面 `pip`。** `pip3 install ".[research]"` 合法，而 `"pip" in
command` 把它整条排除在推导覆盖面之外。与「认目标不认 flag」同一课，这次轮到
可执行体：pip 的命名方案（`pip` + 版本后缀，如 `pip3`、`pip3.12`）是它安装器
写死的，不是开放集合；路径前缀取 basename，`python -m pip` 由裸 `pip` token
覆盖，`pipx` 这种形近的不算。

**P1 各轮 commit 正文里的数字在 squash 后会串联落到 main。** 每轮的数字都是
当轮实测（原样呈报纪律），但本仓 squash 合并把各 commit message 串成 main 上
那一条的正文——于是首轮的 450/827/7 与末轮的 474/846/33 会并排出现，读者无从
分辨哪个描述最终态。不改史（旧正文的数字改成后来值反而是造假：那些数字没在
那个 diff 上量过）；处置＝末轮 commit 正文显式声明「最终实测，覆盖此前各轮
同类数字」，tasks.md 已标「最终一轮实测」。若要彻底消除并排数字，只能改写
分支历史（force-push）或在 merge 时手工编辑 squash message——呈裁决。

## codex 第六轮：两个词法 + 一个 TOML —— 一次把层次抬到底

三条意见（相邻分隔符 `a&&b`、行末反斜杠续行、TOML 单引号字面量）看着是三种
写法，根子是**同一个**：我在用近似手段做词法分析，而且**读不懂时静默跳过**。

`shlex` 是**分词器**，它不知道命令在哪里结束——没有空格的 `&&` 被它切成一个
词，续行让它当场抛，而两种情况下守卫的反应都是「返回空」：那一段的覆盖面是
空的，且空得看不出来。同理，在 `pyproject.toml` 上找 `"…"` 只认了 TOML 两种
字符串语法里的一种。

所以这一轮不补写法，改判据的**层次**：workflow 的 `run` 块按 shell **词法**
扫（单引号、双引号、反斜杠转义、注释、行末续行、here-document、命令分隔符
——一个有限闭集），pyproject 按 **TOML 解析**；读不下去的内容**响亮报错**，
不再静默跳过。仓库里那段 `python - <<'EOF'` 正是靠新认的 here-document 构件
才读得干净。

副产品：`requires-python` 收 3.10，而 `tomllib` 是 3.11 才进标准库的——所以
`tomli` 在 3.10 上是一条**真依赖**，按本 change 自己的规矩加了小版本上界。

## codex 第五轮：一个 P1 + 一个 P2 —— 两条都升级判读

**P1 一条物理行可以串起好几条命令。** `pip install git+…qlib… && pip install
"numpy…"` 里两个约束确实都在这一行，但 qlib 那次解析仍然是无约束的——正是本
守卫要拦的那条路。修法不是再加一条字符串规则，而是按 **POSIX shell 的命令
分隔符闭集**（`&& || ; | &`）把 token 列表切成命令；引号里的 `&&` 由 `shlex`
处理，不是特例。

**P2 只认 `-e` 一种写法。** pip 还支持 `--editable`，以及不带任何 flag 的
`pip install ".[research]"`。一个个去认 flag 又是「字面形态」那条老路。改为
**认目标不认 flag**：`.` 或 `.[组]` 长什么样，与用了哪种写法无关。这一条是
**删代码**——flag 处理整段没了。

## codex 第四轮：一个 P1 + 两个 P2 —— 判读升级

三轮下来同一个根：**我在逐类枚举「CI 装了什么」**，extras（首版）→ base 依赖
（第二轮）→ 构建依赖（本轮）。每轮 codex 指出又少一类。

正确判据不是再补一类，而是从**声明本身**取：pyproject 能承载 requirement 的
位置是标准定的**闭集**，只有三处——PEP 518 `[build-system].requires`、PEP 621
`[project].dependencies`、`[project.optional-dependencies].<组>`。覆盖面按这个
闭集取，枚举就此终结。（`pip install -e .` 缺省走隔离构建，pip 独立解析
build-system.requires；CI 实测装到 setuptools 84.0.0，而声明是 `>=68` 无上界。）

另两条（step `name:` 里的假安装、单引号写的重述）属于「字面形态」那一带：
注释 → 元数据字段 → 引号样式，每补一条只是往同一堆字符串规则上再加一条。
**没有加第三条规则**，改成按结构解析：YAML 取 `steps[].run`（那才是会执行的），
`shlex` 切词后比对实参。引号形态与非可执行字段就此不再是特例。

## 自己守卫里的静默缩水（本轮变异抓到）

放宽 `_requirement_block` 正则以支持单行 `requires = [...]` 时，我把注释放在
**定位块之后**才剥——于是注释里任何一个 `]`（比如一句提到 `.[dev,ui]` 的说明）
让非贪婪匹配提前收尾：`dependencies` 只读到 9 条里的 3 条、`ui` 读到 0 条，而
整体计数下限仍然满足。**这正是本文件一路在替别处修的那种毛病，我自己犯了。**

修法：注释先剥再定位；每组读到 0 条即响亮失败；并直接对着 helper 写了一组用例
（注释里带 `]`、开头就是带 `]` 的注释、单行列表、空读要炸）。

## codex 第三轮：一个 P1 + 两个 P2

**P1 约束要挂在装 qlib 的那条命令上**。我在整份 workflow 里找重述，而不是在
那条命令上找。qlib 若丢了参数、而同一文件别处（另一条命令、甚至一段注释）仍
留着那两个串，守卫照样绿——而 `test.yml` 自己记着：没有约束的首次解析会装出
numpy-2 era 的 scipy，随后的降级会打断 `qlib.backtest` 的 import 链。**约束的
作用点是那条命令，判据也必须落在那条命令上。**

**P2 重述扫描不该按 qlib URL 过滤**。上一轮我把 workflow 先按「含 qlib URL」
筛了一道，于是一个为别的安装路径重述同一窗口的新 workflow 永远不会被检查——
而「新 workflow 重述了窗口就要自动被查」正是我自己刚写下的场景。拆成两条：
扫全部 workflow 比整串；再单独要求 qlib 那条命令带齐。

**P2 注释掉的命令不算安装**。正则跑在原始文本上，一句

## 两条「变异没抓到」的处置

- **G**（安装行改格式）：扫单文件时集合会变空、断言当场炸；扫全部之后另一个
  workflow 仍能解析，这一个的覆盖面**静默缩水**。补：凡做 editable 安装的
  workflow，那行都必须解析得出。
- **N**（遍历退回只走 extra）：base 依赖现在个个有上界，移除覆盖面不改变任何
  判定。补法不是再加一层 AST 去盯测试（那是 detector-of-detector），而是让上界
  检查**对自己实际用到的覆盖面作证**——用它手里那个变量断言。

## 自审留档：一次被自己证伪的「发现」

首版之后我自审出一条「洞」：环境标记里的 `<`（`tomli; python_version<'3.11'`）
会被上界检查误判为已有上界。于是加了个 `_version_part` 先砍掉 `;` 之后的标记。

**那条「先证明前提」的用例当场把它证伪了**：`_UPPER_BOUND` 是
`(<=?|==|~=)\s*\d`，要求操作符后面紧跟**数字**，而 PEP 508 的标记值必须加引号，
`<` 之后是引号。洞不存在，`_version_part` 是一段永远走不到的防御代码——删掉。

但变异测试接着指出第二层：把 `\s*\d` 去掉，依赖表上**没有任何用例会红**。因为
放宽只会让正则更宽容，而现有条目个个都带真上界。所以那一位是**承重且未测**的
——补的不是代码，是一条直接对着正则的用例。

三步各自不同：redundant 的辅助函数该删；承重的性质该测；而分辨这两者靠的是
「先证明前提」+ 变异，不是直觉。
