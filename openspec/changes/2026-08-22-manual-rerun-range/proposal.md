# 手动补跑要能控制范围，并在会空转时先说一声

## Why

运行中心的「手动补跑」是漏跑/失败之后的唯一自助通道。它有两个洞，都在这个月被
真实撞到过：

**一、范围写死。** 2026-08-17 / 08-20 / 08-21 连续三晚失败，因为一次收盘前的更宽
范围抓取把 fetch manifest 撑到 20151001 并记下未解决的洞；此后每次按缺省下限
`--start-date 20180101` 跑都被 manifest 的范围守卫拒绝——它拒绝缩窄合并，因为
更窄的范围不会重试范围外的洞。01 当时就给出了修法（「按完整范围重跑，或传
`--reset-manifest`」），而这个页面**做不到**：范围是写死的。操作人只能去命令行。

**二、周末点下去等于什么都没做。** 交易日历闸在非交易日 no-op 并 **exit 0**——
不抓取、不重建、不切换，而状态工件记成一次**成功**。旁路是传 `--end-date`，
页面同样传不了。补跑那次就是这么空转掉的。

## What Changes

- 手动补跑接受显式的开始/结束日期；**不指定时 argv 与调度器逐字相同**。
- 页面展示的启动参数改为**从构建 argv 的同一次调用派生**，不再手抄一份。
- 日期格式与首尾顺序在按钮之前校验；启动器一侧同样校验（它才是被审计的边界）。
- 日历闸会让本次运行空转时，启动前预警——复现该闸的**完整**条件，且只预警不拦截。

## 那条「镜像调度器」的不变式怎么处理

`test_argv_mirrors_the_scheduler_wrapper` 是 #440 时代 codex 加固过的 FULL-LIST
相等守卫，注释里点名 `--end-date` 属于不许夹带的东西。本改动**没有推翻它，也没
有改它一个字**——它原样保留并仍然绿着，那正是「缺省没动」的机器证明。

它保护的是**被夹带**的参数：操作人没要求、也看不见的那种。本改动里的偏离只能
来自操作人的显式输入，而且页面显示的就是产出的 argv 本身（一条守卫钉住预览与
启动读同一组输入），所以偏离永远是看得见的。

## Non-goals

- **不做 manifest 范围预检。** 那需要在 UI 侧复刻 manifest 自己的范围逻辑——正是
  这个仓库反复付学费的「同一件事写两处」。#462 已经让 01 那句带修法的原因走到
  操作人眼前，本改动让他能照着做；这个闭环已经成立，预检只是把事后变成事前。
- **不给 UI 加节假日感知。** 日历闸刻意只管周末（工作日节假日走正常流程，由
  fetch 的新鲜度闸优雅 no-op）。UI 判得比闸更宽，就是在预警一件不会发生的事。
- 不拦截 no-op。它无害，操作人可能正是要它。
